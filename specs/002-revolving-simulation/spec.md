# 機能仕様：リボ払い（定額方式）の支払シミュレーション

**Feature Branch**: `002-revolving-simulation`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "クレジットカードのリボ払い（定額方式）シミュレーション機能。カード利用者が、リボ払いにしたときに完済までの回数と手数料を事前に確認できるようにする。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完済までの回数と手数料を事前に確かめる (Priority: P1)

カードの利用者が、利用残高・毎月の支払額・実質年率を入力すると、何回で払い終わるのか、
手数料が合計いくらかかるのか、全部でいくら払うのかを、リボ払いにする前に確かめられる。

**Why this priority**: この機能の目的そのもの。これだけで、利用者は毎月の支払額をいくらにするか判断できる。

**Independent Test**: 利用残高・毎月の支払額・実質年率を入力してシミュレーションを実行し、
完済までの支払回数・手数料の合計・支払総額が、手計算した期待値と1円単位で一致することで確かめられる。

**Acceptance Scenarios**:

1. **Given** 利用残高100,000円・毎月の支払額10,000円・実質年率15.0%を入力した状態, **When** シミュレーションを
   実行する, **Then** 完済までの支払回数は11回、手数料の合計は7,497円、支払総額は107,497円と表示され、
   支払総額 ＝ 利用残高 ＋ 手数料の合計 が成り立つ
2. **Given** 利用残高100,000円・毎月の支払額10,000円・実質年率0.0%を入力した状態, **When** シミュレーションを
   実行する, **Then** 完済までの支払回数は10回、手数料の合計は0円、支払総額は100,000円である
3. **Given** 毎月の支払額を大きくした条件, **When** 同じ利用残高・実質年率でシミュレーションを実行する,
   **Then** 完済までの支払回数と手数料の合計は、小さい支払額のときより多くならない

### User Story 2 - 返済表で回ごとの内訳を見る (Priority: P2)

利用者が、1回目から完済する回までの各回について、支払額・そのうちの元金と手数料・
支払後の残高を、返済表で確かめられる。

**Why this priority**: 残高がどう減っていくか、手数料がどれだけかかっているかが分かり、
リボ払いの負担を実感できる。ただし、P1だけでも判断はできる。

**Independent Test**: シミュレーションの結果に、完済までの支払回数と同じ行数の返済表が表示され、
各列の合計と最終回の残高が FR-009〜FR-011 を満たすことで確かめられる。

**Acceptance Scenarios**:

1. **Given** シミュレーションを実行した状態, **When** 返済表を見る,
   **Then** 1回目から完済する回までの行があり、各行に回・支払額・元金・手数料・支払後の残高がある
2. **Given** 返済表を表示した状態, **When** 各回の支払額を合計する, **Then** 合計は支払総額と一致する
3. **Given** 返済表を表示した状態, **When** 各回の元金を合計する, **Then** 合計は利用残高と一致する
4. **Given** 返済表を表示した状態, **When** 最終回の行を見る, **Then** 支払後の残高は0円である
5. **Given** 返済表を表示した状態, **When** 最終回より前の行を見る,
   **Then** 支払額はすべて、入力した毎月の支払額と同じである
6. **Given** 利用残高100,000円・毎月の支払額10,000円・実質年率15.0%でシミュレーションを実行した状態,
   **When** 返済表を見る, **Then** 全11行が次の表のとおりである（金額の単位は円）

   | 回 | 支払額 | 手数料 | 元金 | 支払後の残高 |

   | 2 | 10,000 | 1,140 | 8,860 | 82,390 |
   | 3 | 10,000 | 1,029 | 8,971 | 73,419 |
   | 4 | 10,000 | 917 | 9,083 | 64,336 |
   | 5 | 10,000 | 804 | 9,196 | 55,140 |
   | 6 | 10,000 | 689 | 9,311 | 45,829 |
   | 7 | 10,000 | 572 | 9,428 | 36,401 |
   | 8 | 10,000 | 455 | 9,545 | 26,856 |

   | 11 | 7,497 | 92 | 7,405 | 0 |

7. **Given** 利用残高1,000円・毎月の支払額1,000円・実質年率15.0%でシミュレーションを実行した状態,
   **When** 返済表を見る, **Then** 1回目は支払額1,000円・手数料12円・元金988円・残高12円、
   2回目（最終回）は支払額12円・手数料0円・元金12円・残高0円である

### User Story 3 - 誤った入力に気づいて直す (Priority: P3)

利用者が、未入力の項目や範囲外の値、払い終わらない支払額を入力してシミュレーションを実行すると、
計算は行われず、どの項目をどう直せばよいかが分かる。

**Why this priority**: 誤った結果や終わらない計算を見せないために必要。正しい入力の流れ（P1）が先にあって意味を持つ。

**Independent Test**: 未入力・範囲外・形式の誤り・払い終わらない支払額の各入力でシミュレーションを実行し、
結果が表示されず、項目ごとのエラーメッセージが表示されることで確かめられる。

**Acceptance Scenarios**:

1. **Given** 利用残高が未入力の状態, **When** シミュレーションを実行する,
   **Then** 結果は表示されず、利用残高の項目に「入力してください」という趣旨のメッセージが表示される
2. **Given** 利用残高が上限を1円超えている状態, **When** シミュレーションを実行する,
   **Then** 結果は表示されず、入力できる範囲がメッセージで示される
3. **Given** 毎月の支払額が1,000円単位でない状態（例：1,500円）, **When** シミュレーションを実行する,
   **Then** 結果は表示されず、毎月の支払額の項目に、入力できる額の条件がメッセージで示される
4. **Given** 利用残高10,000,000円・毎月の支払額125,000円・実質年率15.0%を入力した状態
   （1回目の手数料が125,000円で、支払額と同じ）, **When** シミュレーションを実行する,
   **Then** 結果は表示されず、毎月の支払額を1回目の手数料より大きくするよう、メッセージで示される
5. **Given** 利用残高10,000,000円・毎月の支払額126,000円・実質年率15.0%を入力した状態
   （完済までに390回かかる）, **When** シミュレーションを実行する,
   **Then** 結果は表示されず、完済までの回数が360回を超えることと、支払額を増やすことがメッセージで示される
6. **Given** 利用残高10,000,000円・毎月の支払額127,000円・実質年率15.0%を入力した状態,
   **When** シミュレーションを実行する, **Then** 完済までの支払回数は335回で、結果が表示される
7. **Given** 複数の項目が誤っている状態, **When** シミュレーションを実行する,
   **Then** 誤っているすべての項目に、それぞれのメッセージが表示される

---

### Edge Cases

- 実質年率が0.0%のとき：手数料は0円になり、支払総額は利用残高と一致する
- 毎月の支払額が利用残高と同じとき：実質年率が0.0%なら1回で完済する。0.0%より大きければ、
  1回目の手数料の分だけ残高が残り、2回で完済する（受け入れ条件 P2-7）
- 最終回の支払額は、毎月の支払額以下になる（残高＋その回の手数料が、ちょうど毎月の支払額と同じなら同じ額）
- 毎月の支払額が利用残高を超えるとき：入力エラーになる（FR-004）
- 利用残高・実質年率が、上限ちょうど・下限ちょうどのとき：計算できる
- 上限を1単位超える・下限を1単位下回るとき：入力エラーになる
- 利用残高・毎月の支払額に小数・負の数・数字以外の文字が入力されたとき：入力エラーになる
- 実質年率に、小数第2位以下の値（例：12.25%）が入力されたとき：入力エラーになる（勝手に丸めない）
- 毎月の支払額が1回目の手数料以下のとき、または完済までの回数が360回を超えるとき：入力エラーになる（FR-004）
- 完済までの回数がちょうど360回のとき：計算できる

## Requirements *(mandatory)*

### Functional Requirements

**入力**

- **FR-001**: 利用者は、利用残高（円）・毎月の支払額（円）・実質年率（%）を入力できなければならない。3項目とも必須とする。
- **FR-002**: 利用残高は1円単位の整数で、1,000円以上10,000,000円以下でなければならない（分割払いの利用金額とそろえる）。
- **FR-003**: 実質年率は0.0%以上15.0%以下で、小数第1位までの値でなければならない（分割払いとそろえる）。
- **FR-004**: 毎月の支払額は、1,000円以上・1,000円単位で、利用残高以下でなければならない。
  さらに、次のどちらかに当たる条件は、入力エラーとする。
  - 毎月の支払額が、1回目の手数料（利用残高 × 月利 の1円未満を切り捨てた額）以下である（残高が減らず、払い終わらない）
  - 完済までの支払回数が、360回（30年）を超える
- **FR-005**: 入力が FR-001〜FR-004 を満たさないとき、システムは計算を行わず、誤っているすべての項目に、
  直し方が分かるメッセージを表示しなければならない。

**計算**

- **FR-006**: 定額方式の種類は、元利定額方式とする。毎月の支払額は手数料込みで決まった額とし、
  その回の元金は「毎月の支払額 − その回の手数料」とする。元金定額方式は扱わない。
- **FR-007**: システムは、次の「手数料の計算方式と端数処理のルール」に従って計算しなければならない。
  以下、月利 ＝ 実質年率 ÷ 12 とする（日割り計算はしない）。

  | 項目 | 計算方法 | 端数処理 |
  |------|----------|----------|
  | 各回の手数料 | 前回の支払後の残高 × 月利（1回目は利用残高 × 月利） | 1円未満を切り捨てる |
  | 最終回の判定 | 前回の支払後の残高 ＋ その回の手数料 が、毎月の支払額以下になった回を最終回とする | — |
  | 支払額（最終回より前） | 毎月の支払額 | 端数は出ない |
  | 支払額（最終回） | 前回の支払後の残高 ＋ その回の手数料 | 端数は出ない |
  | 元金 | その回の支払額 − その回の手数料（最終回は、前回の支払後の残高と同じ額になる） | 端数は出ない |
  | 支払後の残高 | 前回の支払後の残高 − その回の元金 | 端数は出ない |
  | 手数料の合計 | 各回の手数料の合計 | 端数は出ない |
  | 支払総額 | 利用残高 ＋ 手数料の合計 | 端数は出ない |
  | 完済までの支払回数 | 最終回の回 | — |

- **FR-008**: 実質年率が0.0%のときは、各回の手数料はすべて0円とする。
- **FR-009**: 返済表の各回の支払額の合計は、支払総額と一致しなければならない。
- **FR-010**: 返済表の各回の元金の合計は、利用残高と一致しなければならない。
- **FR-011**: 返済表の最終回の支払後の残高は、0円でなければならない。
- **FR-012**: 金額の計算は、途中で誤差の出ない方法で行い、丸めは FR-007 に書いた箇所でだけ
  行わなければならない（constitution 原則III）。

**出力**

- **FR-013**: システムは、完済までの支払回数・手数料の合計・支払総額を表示しなければならない。
- **FR-014**: システムは、返済表（回・支払額・元金・手数料・支払後の残高）を、1回目から完済する回まで表示しなければならない。
- **FR-015**: 金額は円単位で、3桁ごとに区切って表示しなければならない。

**画面の入力欄の表示（Should）**

2026-11-25 に、ユーザーの判断で追加した。分割払い（`specs/001-installment-simulation/spec.md` の FR-015〜FR-018）と同じ動きにそろえる。
以下は、満たすことが望ましい（Should）要件とする。

- **FR-016**: 利用残高と毎月の支払額の入力欄は、フォーカスが外れたときに、入力された値を3桁区切りのカンマを付けて表示するとよい
  （例：`100000` → `100,000`）。API に送るときは、カンマを取り除いて送る。
  利用者が自分でカンマを入れた値（例：`100,000`）も、同じくカンマを取り除いて送り、受け付ける。
  カンマを取り除いても半角数字だけにならない値（例：`abc`・`1000.5`）は整えず、入力されたまま残す
  （API の入力チェックで、形式の誤りになる）。
- **FR-017**: 実質年率の入力欄は、整数が入力されたとき、フォーカスが外れたときに小数第1位まで表示するとよい
  （例：`15` → `15.0`）。整数でない値（例：`abc`・`12.25`）は整えず、入力されたまま残す。
- **FR-018**: FR-016・FR-017 で値を整えるのは画面の中だけとし、API の入力のルール（カンマ付きの金額は形式の誤り。
  [contracts](contracts/revolving-simulation-api.md)）は変えない。毎月の支払額の「1,000円単位」「利用残高以下」のチェックも、今までどおり API が行う。
- **FR-019**: 入力中（フォーカスがある間）は、カンマを差し込まない（カーソルの位置がずれるため）。

### Key Entities

- **シミュレーション条件**：利用残高・毎月の支払額・実質年率。
- **シミュレーション結果**：完済までの支払回数・手数料の合計・支払総額・返済表。
- **返済表の行**：回（1〜完済までの支払回数）・支払額・元金・手数料・支払後の残高。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は、画面を開いてから30秒以内に、シミュレーション結果を確かめられる。
- **SC-002**: あらかじめ用意した検証用の条件（端数が出る条件・年率0%・1回で完済する条件・上限と下限を含む）のすべてで、
  結果が手計算の期待値と1円単位で一致する。
- **SC-003**: すべての結果で、支払額の合計＝支払総額、元金の合計＝利用残高、最終回の残高＝0円 が成り立つ。
- **SC-004**: 未入力・範囲外・形式の誤り・払い終わらない支払額の入力は100%入力エラーになり、
  誤った計算結果が表示されることはない。
- **SC-005**: 入力してから結果が表示されるまで、1秒以内である（完済までの回数が上限のときも含む）。

## Assumptions

- 範囲外：認証・ログイン、実際の決済、本物のカード番号の扱い、残高スライド方式、追加の利用、繰上げ返済、
  分割払い（`specs/001-installment-simulation/spec.md` に別の仕様がある）。
- MVPの範囲に挙がっていないため、結果の保存、支払額ごとの比較表も範囲外とする（constitution 原則VIII）。
- この機能では、カード番号や個人情報を入力・保存しない。
- 利用残高の範囲・実質年率の範囲と桁数・月利の求め方・手数料の切り捨ては、分割払いの仕様とそろえた。
- 手数料は、毎月の残高に対して1か月分の月利で計算する。締め日・支払日・日割りは扱わない。
- 支払回は「1回目・2回目…」で表し、具体的な支払日（年月日）は扱わない。
- 1回目の手数料は、利用残高 × 月利 とする（利用した月の手数料を別に計算しない）。
