# 0011 DB：PostgreSQL＋Flyway

## 状態

Accepted（2026-11-17）

## 背景

- 申込管理では、申込・状態・変更履歴を、システムを再起動しても消えないように保存する必要がある（`specs/003-card-application/spec.md` FR-005・SC-005）。
- 金額は誤差なく扱う必要がある（constitution 原則III）。
- DBはEC2上のdocker composeで動かす（[0009](0009-デプロイ構成.md)）。
- バックエンドはSpring Boot（[0001](0001-技術スタック.md)）。

## 決定

- DBはPostgreSQLを使う。
- DBの変更（テーブルの作成・変更）はFlywayで管理する。

選んだ理由：

- PostgreSQL
  - 無料のOSSで、実績が多い。
  - 金額を誤差なく保存できるNUMERIC型がある。
  - 公式のDockerイメージがあり、docker composeで動かせる。将来RDSへ移すこともできる。
- Flyway
  - SQLをそのまま書けて、シンプル。
  - Spring Bootが標準で対応している。
  - DBの変更をバージョンで管理できる。

## 検討した他の案

| 案 | 採らなかった理由 |
|---|---|
| MySQL | DECIMAL型で金額を誤差なく扱えるので、要件上の差は小さい。PostgreSQLは型の扱いが厳格で、金融系でも採用が多いため、PostgreSQLを選んだ。 |
| Liquibase | Flywayの方が、SQLをそのまま書けてシンプル。 |

## 結果

### 良い影響

- 金額をNUMERIC型で保存すれば、`BigDecimal`と誤差なくやり取りできる。
- 開発環境とEC2で、同じDockerイメージを使える。
- DBの変更がリポジトリに残り、どの環境でも同じ順番で適用できる。
- EC2上のDBで困ったら、RDSへ移す道がある。

### 悪い影響

- 一度適用したマイグレーションのファイルは書き換えられない。直すときは新しいバージョンのファイルを足す必要がある。
