# データモデル（Phase 1）：分割払いの支払シミュレーション

**対象**: [spec.md](spec.md) ／ **計画**: [plan.md](plan.md)

この機能は計算だけで、DB に保存しない（[research.md](research.md) R10）。
ここに書くのは、計算の入力と出力、API でやり取りする項目の形である。
API の JSON の形は [contracts/installment-simulation-api.md](contracts/installment-simulation-api.md) を正とする。

## 1. シミュレーション条件（InstallmentCondition）

入力チェックを通ったあとの、計算に渡す値。

| 項目 | API の名前 | Java の型 | ルール | 根拠 |
|---|---|---|---|---|
| 利用金額（円） | `amount` | `BigDecimal`（小数なし） | 必須。整数。1,000以上10,000,000以下 | FR-001・FR-002 |
| 支払回数 | `paymentCount` | `int` | 必須。3・5・6・10・12・15・18・20・24・30・36 のいずれか | FR-001・FR-003 |
| 実質年率（%） | `annualRate` | `BigDecimal`（小数第1位まで） | 必須。0.0以上15.0以下。小数第2位以下があればエラー（丸めない） | FR-001・FR-004 |

### 入力（文字列）の解釈のルール

API は3項目を文字列で受け取る（[research.md](research.md) R6）。サーバーは次の順に確かめ、
**項目ごとに最初に当てはまった1つ**のエラーを返す。3項目はそれぞれ独立に確かめ、誤っている項目はすべて返す（FR-005）。

| 項目 | 1. 必須 | 2. 形式 | 3. 範囲 |
|---|---|---|---|
| 利用金額 | 未指定・空文字・空白だけ → エラー | 半角数字だけ（`^[0-9]+$`）でない → エラー。小数・負の数・カンマ・全角数字もここでエラー | 1,000未満・10,000,000超 → エラー |
| 支払回数 | 未指定・空文字・空白だけ → エラー | 半角数字だけでない → エラー | 一覧にない回数 → エラー |
| 実質年率 | 未指定・空文字・空白だけ → エラー | `^[0-9]+(\.[0-9])?$` でない → エラー。`12.25`・`-1`・`.5`・`abc` はここでエラー | 0.0未満・15.0超 → エラー |

- 前後の空白は取り除いてから確かめる。
- 先頭の0（`01000`）は受け付け、1000 として扱う。
- 支払回数は形式と一覧のチェックを1つのメッセージにまとめてよい（メッセージは contracts を参照）。

## 2. シミュレーション結果（InstallmentResult）

| 項目 | API の名前 | Java の型 | 計算 | 根拠 |
|---|---|---|---|---|
| 手数料の総額（円） | `totalFee` | `BigDecimal`（小数なし） | FR-006（年率0%は FR-007 で0円） | FR-006・FR-007 |
| 支払総額（円） | `totalPayment` | `BigDecimal`（小数なし） | 利用金額 ＋ 手数料の総額 | FR-006 |
| 初回の支払額（円） | `firstPayment` | `BigDecimal`（小数なし） | 支払総額 −（2回目以降の支払額 ×（n − 1）） | FR-006・FR-007 |
| 2回目以降の支払額（円） | `subsequentPayment` | `BigDecimal`（小数なし） | 支払総額 ÷ n の1円未満を切り捨て | FR-006・FR-007 |
| 返済表 | `schedule` | `List<ScheduleRow>` | 3 を参照 | FR-013 |

**守られる関係（不変条件）**:

- 支払総額 ＝ 利用金額 ＋ 手数料の総額
- 初回の支払額 ≧ 2回目以降の支払額（差額は初回に寄せるため）
- `schedule` の行数 ＝ 支払回数

画面は、`firstPayment` と `subsequentPayment` が異なるときだけ、初回と2回目以降を分けて表示する（FR-012）。

## 3. 返済表の行（ScheduleRow）

| 項目 | API の名前 | Java の型 | 計算 | 根拠 |
|---|---|---|---|---|
| 回 | `number` | `int` | 1〜支払回数 | FR-013 |
| 支払額（円） | `payment` | `BigDecimal`（小数なし） | 1回目は初回の支払額、2回目以降は2回目以降の支払額 | FR-006 |
| 元金（円） | `principal` | `BigDecimal`（小数なし） | 支払額 − その回の手数料 | FR-006 |
| 手数料（円） | `fee` | `BigDecimal`（小数なし） | 最終回の1つ前まで：前回の残高 × 月利 の1円未満を切り捨て。最終回：手数料の総額 − それまでの手数料の合計。年率0%はすべて0円 | FR-006・FR-007 |
| 支払後の残高（円） | `balanceAfter` | `BigDecimal`（小数なし） | 前回の残高 − その回の元金 | FR-006 |

**守られる関係（不変条件）**:

- 各行の支払額の合計 ＝ 支払総額（FR-008）
- 各行の元金の合計 ＝ 利用金額（FR-009）
- 最終回の支払後の残高 ＝ 0（FR-010）
- 各行の手数料の合計 ＝ 手数料の総額
- 元金・残高は負にならない（[research.md](research.md) R7 で、条件の範囲を広く確かめた）
- 最終回の手数料は、その回の元金より大きくなることがある（spec のエッジケース）

## 4. 計算の手順

計算式は spec の FR-006・FR-007 を正とする。誤差を出さないための式の変形（割り算を最後の1回にまとめる）は
[research.md](research.md) R7 を参照。

1. k ＝ 実質年率 × 10（0〜150 の整数）。
2. k ＝ 0 なら FR-007：手数料はすべて0、2回目以降の支払額 ＝ 切り捨て(利用金額 ÷ n)、初回 ＝ 利用金額 − 2回目以降 ×（n − 1）。
3. k ＞ 0 なら FR-006：R7 の式で手数料の総額を求め、支払総額・2回目以降・初回の支払額を順に求める。
4. 返済表を1回目から順に作る。残高は利用金額から始める。

## 5. 状態の遷移

なし。計算は毎回独立していて、前回の結果を持たない（spec のエッジケース「入力を直して再度実行したとき」）。
