# データモデル（Phase 1）：リボ払い（定額方式）の支払シミュレーション

**対象**: [spec.md](spec.md) ／ **計画**: [plan.md](plan.md)

この機能は計算だけで、DB に保存しない（[research.md](research.md) R1）。
ここに書くのは、計算の入力と出力、API でやり取りする項目の形である。
API の JSON の形は [contracts/revolving-simulation-api.md](contracts/revolving-simulation-api.md) を正とする。
項目名は [research.md](research.md) R3 で決めた（2026-11-24 に採用）。

## 1. シミュレーション条件（RevolvingCondition）

入力チェックを通ったあとの値。

| 項目 | API の名前 | Java の型 | ルール | 根拠 |
|---|---|---|---|---|
| 利用残高（円） | `balance` | `BigDecimal`（小数なし） | 必須。整数。1,000以上10,000,000以下 | FR-001・FR-002 |
| 毎月の支払額（円） | `monthlyPayment` | `BigDecimal`（小数なし） | 必須。整数。1,000以上・1,000円単位・利用残高以下。1回目の手数料より大きく、完済までの回数が360回以内 | FR-001・FR-004 |
| 実質年率（%） | `annualRate` | `BigDecimal`（小数第1位まで） | 必須。0.0以上15.0以下。小数第2位以下があればエラー（丸めない） | FR-001・FR-003 |

### 入力（文字列）の解釈のルール

分割払いのルール（`specs/001-installment-simulation/data-model.md` 1）と同じ決め方にする。

- API は3項目を文字列で受け取る。前後の空白を取り除いてから確かめる。
- 項目ごとに、表の左から順に確かめ、**最初に当てはまった1つ**のエラーを返す。誤っている項目はすべて返す（FR-005）。
- 3項目とも、長さの上限は20文字（前後の空白を取り除いたあとの文字数）。形式に合っていて上限を超えたものは、範囲の誤りとする。
  形式に合わないものは、長さにかかわらず形式の誤りとする。
- 先頭の0（`01000`）は受け付け、数として扱う。カンマ付き（`100,000`）・小数第2位まで書いた年率（`15.00`）は形式の誤り。
  API のこのルールは変えない（FR-018）。画面は FR-016（Should。2026-11-25 に追加）により、利用残高・毎月の支払額で、前後の空白とカンマを取り除くと
  半角数字だけになる値（例：`100,000`・`100,000 `）は、空白とカンマを取り除いてから送る。そうならない値（例：`1,000.5`）は入力されたまま送り、形式の誤りになる。

| 項目 | 1. 必須 | 2. 形式 | 3. 範囲 | 4. ほかの項目との関係【提案】 |
|---|---|---|---|---|
| 利用残高 | 未指定・空文字・空白だけ → エラー | `^[0-9]+$` でない → エラー（小数・負の数・カンマ・全角数字を含む） | 1,000未満・10,000,000超・20文字超 → エラー | なし |
| 毎月の支払額 | 同上 | 同上 | 1,000未満・10,000,000超・1,000で割り切れない・20文字超 → エラー | 4-1：利用残高を超える → エラー（利用残高が 1〜3 を通ったときだけ）<br>4-2：1回目の手数料以下 → エラー（3項目すべてが 1〜4-1 を通ったときだけ）<br>4-3：完済までの回数が360回超 → エラー（4-2 を通ったときだけ） |
| 実質年率 | 同上 | `^[0-9]+(\.[0-9])?$` でない → エラー | 15.0超・20文字超 → エラー | なし |

- 4-1〜4-3 の順番と、確かめる条件の理由は [research.md](research.md) R4。
- 4-2・4-3 は計算が要るので、`RevolvingCalculator` が判断し（3 の例外）、`RevolvingInputValidator` がメッセージに変える。
- 利用残高・実質年率の 1〜3 は、分割払いの利用金額・実質年率と同じルール。共通の `InputRules`（[research.md](research.md) R6）を使う。

## 2. シミュレーション結果（RevolvingResult）

| 項目 | API の名前 | Java の型 | 計算 | 根拠 |
|---|---|---|---|---|
| 完済までの支払回数 | `paymentCount` | `int` | 最終回の回（1〜360） | FR-007 |
| 手数料の合計（円） | `totalFee` | `BigDecimal`（小数なし） | 各回の手数料の合計 | FR-007 |
| 支払総額（円） | `totalPayment` | `BigDecimal`（小数なし） | 利用残高 ＋ 手数料の合計 | FR-007 |
| 返済表 | `schedule` | `List<ScheduleRow>` | 3 を参照 | FR-014 |

**守られる関係（不変条件）**:

- 支払総額 ＝ 利用残高 ＋ 手数料の合計
- `schedule` の行数 ＝ 完済までの支払回数（1〜360）
- 年率0%のとき、手数料の合計 ＝ 0、完済までの支払回数 ＝ 切り上げ(利用残高 ÷ 毎月の支払額)（FR-008）

## 3. 返済表の行（ScheduleRow。分割払いと共通）

分割払いと項目・意味が同じなので、共通の `common/domain/ScheduleRow` を使う（【提案】[research.md](research.md) R6）。
API のレスポンスには、共通の `common/web/ScheduleRowResponse` に変えて返す。

| 項目 | API の名前 | Java の型 | 計算 | 根拠 |
|---|---|---|---|---|
| 回 | `number` | `int` | 1〜完済までの支払回数 | FR-014 |
| 支払額（円） | `payment` | `BigDecimal`（小数なし） | 最終回より前：毎月の支払額。最終回：前回の残高 ＋ その回の手数料 | FR-007 |
| 手数料（円） | `fee` | `BigDecimal`（小数なし） | 切り捨て(前回の残高 × 月利)。1回目は利用残高 × 月利。年率0%は0円 | FR-007・FR-008 |
| 元金（円） | `principal` | `BigDecimal`（小数なし） | 支払額 − その回の手数料（最終回は前回の残高と同じ） | FR-006・FR-007 |
| 支払後の残高（円） | `balanceAfter` | `BigDecimal`（小数なし） | 前回の残高 − その回の元金 | FR-007 |

**守られる関係（不変条件）**:

- 各行の支払額の合計 ＝ 支払総額（FR-009）
- 各行の元金の合計 ＝ 利用残高（FR-010）
- 最終回の支払後の残高 ＝ 0（FR-011）
- 各行の手数料の合計 ＝ 手数料の合計
- 最終回より前の行の支払額 ＝ 毎月の支払額。最終回の支払額 ≦ 毎月の支払額（spec のエッジケース）
- 元金は正、残高は負にならない（1 の 4-2 で、毎月の支払額 ＞ 1回目の手数料 を確かめるため。残高は減っていくので、2回目以降の手数料は1回目以下になる）

## 4. 計算の手順

計算式は spec の FR-006〜FR-008 を正とする（[research.md](research.md) R2）。

1. k ＝ 実質年率 × 10（0〜150 の整数。整数でなければ例外にする）。
2. 1回目の手数料 ＝ 切り捨て(利用残高 × k ÷ 12,000)。これが毎月の支払額以上なら、`RevolvingNotPayableException`（`FEE_NOT_COVERED`）を投げる。
3. 残高を利用残高から始め、1回目から順に次を繰り返す。
   1. 手数料 ＝ 切り捨て(残高 × k ÷ 12,000)。
   2. 残高 ＋ 手数料 ≦ 毎月の支払額 なら最終回：支払額 ＝ 残高 ＋ 手数料、元金 ＝ 残高、支払後の残高 ＝ 0。行を足して終わる。
   3. そうでなければ：支払額 ＝ 毎月の支払額、元金 ＝ 支払額 − 手数料、残高 ＝ 残高 − 元金。行を足す。
   4. 足した行が360行になっても最終回に来ていなければ、`RevolvingNotPayableException`（`TOO_MANY_PAYMENTS`）を投げる（361回目は計算しない）。
4. 手数料の合計 ＝ 各行の手数料の合計、支払総額 ＝ 利用残高 ＋ 手数料の合計、完済までの支払回数 ＝ 行数。

## 5. 払い終わらないことを表す例外（RevolvingNotPayableException）【提案】

ドメインの例外（Spring に依存しない）。入力エラーとしてのメッセージは持たない（[research.md](research.md) R4）。

| 理由 | 当てはまる場合 | Web 層で返すエラー |
|---|---|---|
| `FEE_NOT_COVERED` | 毎月の支払額 ≦ 1回目の手数料 | `monthlyPayment` の 4-2 のメッセージ |
| `TOO_MANY_PAYMENTS` | 完済までの回数が360回を超える | `monthlyPayment` の 4-3 のメッセージ |

## 6. 状態の遷移

なし。計算は毎回独立していて、前回の結果を持たない。
