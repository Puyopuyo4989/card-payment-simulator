# 0001 技術スタック：Spring Boot＋React（TypeScript）

## 状態

Accepted（2026-11-17）

## 背景

- クレジットカードの支払シミュレーション（分割払い・リボ払い）とカード申込管理のMVPを、11/27までに作り、EC2にデプロイして説明する（`docs/sprint-plan.md`）。
- constitution 原則V により、フロントエンドとバックエンドはAPIだけでやり取りし、リポジトリは1つ、ビルド成果物も1つ（jar）とする。
- constitution 原則III により、金額は`BigDecimal`で扱う。

## 決定

- バックエンド：Spring Boot（Java）
- フロントエンド：React（TypeScript）
- フロントエンドとバックエンドはAPIでつなぐ（constitution 原則V）。

選んだ理由：

- Spring Boot
  - Javaの経験がある。
  - 金融業界での採用が多い。
  - 金額計算に使う`BigDecimal`が標準で使える。
- React
  - TODOアプリを作った経験がある。
  - リーダーから、フロントエンドの勉強も求められている。

## 検討した他の案

| 案 | 採らなかった理由 |
|---|---|
| TypeScriptで統一する（バックエンドもTypeScript） | バックエンドをTypeScriptで作った経験がない。JavaScriptの数値は浮動小数点なので、金額計算に追加のライブラリが要る。 |
| Next.js | フロントとバックの境界があいまいになり、課題の「分ける」を説明しにくい。使った経験もない。 |

## 結果

### 良い影響

- 金額の計算に、Javaの`BigDecimal`をそのまま使える（constitution 原則III、[0005](0005-金額計算と端数処理.md)）。
- 成果物を1つのjarにまとめられる（constitution 原則V、[0003](0003-リポジトリと成果物.md)）。

### 悪い影響

- バックエンド（Java）とフロントエンド（TypeScript）で言語が2つになり、ビルドツール・テストツール・カバレッジの計測もそれぞれに用意する必要がある（[0002](0002-ビルドツール.md)、[0006](0006-カバレッジ基準.md)、[0012](0012-フロントのビルドとテスト.md)）。
