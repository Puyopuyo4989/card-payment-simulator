# 0007 ツールの使い分け：SpecKitとSuperpowers

## 状態

Accepted（2026-11-17）

## 背景

- Claude Codeに、SpecKitとSuperpowersの2つを入れている。どちらにも、要件を固める・計画を立てる機能がある。
- 判断は人が行い、文書やコードの下書きはAIに任せる（constitution「開発ワークフローと人とAIの分担」）。
- constitution 原則I（TDD必須）を、実装のときに守らせる必要がある。

## 決定

- **SpecKit：何を作るかを決める**（constitution → specify → clarify → plan → tasks → analyze）。
- **Superpowers：どう作るかを守らせる**（test-driven-development・systematic-debugging・requesting-code-review・verification-before-completion）。
- 実装では、tasks.mdのタスクを1つずつ、SuperpowersのTDDで進める。
- Superpowersのbrainstormingとwriting-plansは使わない。
- SpecKitのplan／tasksは、機能ごとに実装日の直前に行う（Day1の実績で変更）。

選んだ理由：

- SpecKitだけでは実装の規律（TDD・レビュー）が弱く、Superpowersだけでは仕様の文書管理が弱い。両方を使い、役割を分けて弱いところを補う。
- Superpowersのbrainstormingとwriting-plansを使うと、SpecKitの成果物（spec・plan・tasks）と二重になる。
- plan／tasksを機能ごとに実装の直前に作ることで、先の機能で学んだことを後の設計に活かせる。Day2に作業が集中することも避けられる。

## 検討した他の案

| 案 | 採らなかった理由 |
|---|---|
| 両方の機能をすべて使う | 仕様・計画の成果物が二重になる。 |
| SpecKitだけを使う | 実装の規律（TDD・レビュー）が弱い。 |
| Superpowersだけを使う | 仕様の文書管理が弱い。 |
| 3機能すべてのplan／tasksを最初にまとめて作る | 先の機能で学んだことを、後の機能の設計に活かせない。Day2に作業が集中する。 |

## 結果

### 良い影響

- 仕様・計画はSpecKitの成果物（`specs/`）だけを見ればよい。
- 実装のときは、SuperpowersのスキルでTDD・完了前の検証を守らせられる。

### 悪い影響

- Superpowersは、brainstormingを使うよう促す。使わないと決めたことを、作業のたびに意識する必要がある。
- Superpowersは`~/.claude`に入り、Codespaceを作り直すと消える（[0004](0004-開発環境.md)）。
