# 0008 品質の多層防御：Claude Code hooks、git hooks、CI＋Ruleset

## 状態

Accepted（2026-11-17）

## 背景

- コードや文書の下書きはAI（Claude Code）が書く。AIのうっかりミス（`rm -rf`、強制push、`.env`の読み取りなど）を、作業させる前に止める仕組みが要る（`docs/sprint-plan.md`「Skills・Hooksの導入計画」）。
- mainへの変更は必ずPRを通し、PRの前にローカルでも確かめる（constitution 原則VI）。理由：ローカルとサーバー側の両方で確かめることで、片方をすり抜けたミスをもう片方で止める。
- どの仕組みも、1つだけでは完全ではない。
  - git hooksは手元で動き、速いが`--no-verify`で飛ばせる。
  - GitHubのRulesetはサーバー側で動き、Bypass listが空なら飛ばせない。ただし無料プランのPrivateリポジトリでは効かない（`docs/ai-review-log.md` #6）。

## 決定

3層で止める。

| 層 | 仕組み | 動く場所・タイミング | 導入日 |
|---|---|---|---|
| ① | Claude Code hooks（PreToolUse・PostToolUse・Stop） | AIが操作した瞬間 | Day1・Day3・Day5 |
| ② | git hooks（lefthook：pre-commit・commit-msg・pre-push） | コミット・push前に手元で | Day3・Day5 |
| ③ | CI（GitHub Actions）＋ GitHub Ruleset | サーバー側で最後に | Day1（Ruleset）・Day3（CI必須） |

- リポジトリはPublicにして、Rulesetでmainへの直接pushを拒否する。
- 1つ入れるたびに、わざと違反して止まるかを確かめる。止めすぎていないかも確かめる。
- Claude Codeが自分自身を縛るhookは、中身の確認と止まるかのテストを必ず人が行う。

### PreToolUseのhook（`.claude/hooks/guard_dangerous_ops.py`）

**目的**：AIのうっかりミスを止めるための安全柵。悪意のない事故（ビルド成果物を消すつもりで`rm -rf`する、pushが拒否されたので`--force`を付ける、`.env`の中身を確認しようとして読む）を防ぐ。**わざと回避しようとする相手への対策ではない。**

**ブロックする対象**：再帰的な強制削除、強制push（`+main`を含む）、`git reset --hard`、`git clean -f`、`find -delete`、`eval`・`bash -c`による間接実行、`.env`・`.env.*`の読み書き（`.env.example`は許可）。

**既知の限界**（詳細は `.claude/hooks/README.md`）：

- 実行時に組み立てられるコマンド（コマンド置換・変数経由）、スクリプトファイル経由、別言語（Python・Nodeなど）での削除や読み込みは止められない。
- gitのエイリアス・設定、シェルのワイルドカード（`cat .e*`など）、同等の別コマンド（`rsync --delete`、`git checkout -- .`など）は止められない。
- `Grep`でディレクトリ全体を検索すると、`.env`の内容がヒットする可能性がある。
- hookが`deny`か終了コード2以外のエラーで終わると、操作がそのまま通る（例：`python3`が無い）。気づきにくい（`docs/ai-review-log.md` #9）。
- `.claude/settings.json`やスクリプトを書き換えれば、hook自体を無効にできる。

hookが動かない場合の二重の備えとして、`settings.json`の`permissions.deny`にも代表的な`.env`系ファイルを列挙している。denyはallowより優先されるため「`.env.*`から`.env.example`だけ除く」とは書けず、名前を個別に列挙している（`docs/ai-review-log.md` #10）。

## 検討した他の案

| 案 | 採らなかった理由 |
|---|---|
| git hooksだけで止める | `--no-verify`で飛ばせる。 |
| CI＋Rulesetだけで止める | サーバー側で止まるまで、ミスに気づけない。AIの操作そのもの（ファイルの削除・`.env`の読み取り）は止められない。 |
| PreToolUseのhookで、すり抜けを完全に防ぐ | 完全な網羅はできない（既知の限界）。目的を「AIのうっかりミス防止」と定め、ほかの層で補う（`docs/ai-review-log.md` #8）。 |

## 結果

### 良い影響

- 1つの層をすり抜けたミスを、ほかの層で止められる。
- 手元で早く気づける層（①②）と、飛ばせない層（③）を両方持てる。
- 説明資料で、3層の防御を図1枚で示せる。

### 悪い影響

- 止めすぎがある（`rm -rf target`、`find -delete`、`echo .env >> .gitignore`など）。別の手段（ビルドツールのclean、Editツール）で進められるので許容し、Day3で邪魔なら許可リストを見直す（`docs/ai-review-log.md` #11）。
- Rulesetを効かせるためにリポジトリをPublicにしたので、秘密情報・本物のカード情報を絶対にコミットできない（constitution 原則IV・VII）。
- 仕組みが増える分、導入とわざと違反して確かめる作業に時間がかかる。
- git hooksが入るまで（Day3まで）は、コミットとpushを人が行う。
