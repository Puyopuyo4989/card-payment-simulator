# 0012 フロントのビルドとテスト：Vite＋Vitest

## 状態

Accepted（2026-11-17）

## 背景

- フロントエンドはReact（TypeScript）（[0001](0001-技術スタック.md)）。
- フロントエンドのビルド結果は、バックエンドのjarに同梱する（[0003](0003-リポジトリと成果物.md)）。
- フロントエンドも、TDDで作り（constitution 原則I）、行・分岐カバレッジ90%以上を満たす（constitution 原則II、[0006](0006-カバレッジ基準.md)）。

## 決定

- ビルドと開発サーバーはViteを使う。
- テストはVitestを使う。

選んだ理由：

- Vite
  - Reactの開発で、現在の標準的な選択肢である。
  - 開発サーバーが速い。
- Vitest
  - Viteの設定をそのまま使える。
  - Jestとほぼ同じ書き方ができる。
  - カバレッジも計測できる。

## 検討した他の案

| 案 | 採らなかった理由 |
|---|---|
| Jest | Viteの設定をそのまま使えない。Vitestなら、Jestとほぼ同じ書き方ができる。 |
| Create React App | 現在は非推奨。 |

## 結果

### 良い影響

- ビルドとテストで設定を1つにまとめられる。
- 開発サーバーが速く、TDDの red → green を早く回せる。
- フロントエンドのカバレッジを、テストと同じツールで計測できる。

### 悪い影響

- Vitestでカバレッジを計測する方法と、計測から除外する対象は、まだ決めていない（[0006](0006-カバレッジ基準.md)、Day3で決定）。
